# 框架

## Ray

### 一、基础定义与背景
Ray 是一个 **Python 原生统一分布式计算框架**，主打 AI/ML 全链路分布式加速，核心目标：**单机代码几乎不改，一键横向扩展到上千 GPU/节点集群**。
定位：AI 时代统一计算引擎，一套框架覆盖**数据处理、分布式训练、超参调优、LLM 推理服务、强化学习**全流程，替代多套异构分布式工具（Spark、DDP、独立推理框架等）。

#### 核心优势
1. **极简分布式 API**：仅用 `@ray.remote` 装饰器即可把函数/类变成分布式任务/服务，屏蔽集群调度、通信、容错细节；
2. **统一资源调度**：精细管控 CPU、GPU、显存，支持 GPU 分片、异构算力混合调度；
3. **无缝伸缩**：本地笔记本、私有集群、K8s(KubeRay)、云厂商(AWS/Azure/GCP)一套代码运行；
4. **内置容错**：节点/进程崩溃自动重试任务、从 checkpoint 恢复训练；
5. **丰富 AI 上层库**：一站式 ML 流水线，深度兼容 PyTorch、TensorFlow、Hugging Face、vLLM、XGBoost。

### 二、整体三层架构
1. **底层：Ray Core（分布式运行时核心）**
    基础分布式原语，所有上层 AI 库均基于它实现；
2. **中层：Ray AI Libraries（ML 专用工具栈）**
    Ray Data / Ray Train / Ray Tune / Ray Serve / RLlib；
3. **顶层：Ray Clusters（集群管理层）**
    集群启动、自动扩缩容、K8s 部署、监控 Dashboard。

### 三、Ray Core 核心三大抽象（底层基础）
#### 1. Task：无状态分布式函数
普通函数加 `@ray.remote`，并行调度在集群任意节点执行，适合批量无状态计算。
```python
import ray
ray.init() # 单机自动启动集群

@ray.remote
def square(x):
    return x * x

# 异步提交任务，返回Future
futures = [square.remote(i) for i in range(4)]
# 同步获取所有结果
print(ray.get(futures)) # [0, 1, 4, 9]
```

#### 2. Actor：有状态分布式实例
类加 `@ray.remote`，长期驻留进程保存可变状态，适合参数服务器、LLM 推理服务、仿真环境、缓存服务。
```python
@ray.remote
class Counter:
    def __init__(self):
        self.count = 0
    def inc(self):
        self.count += 1
        return self.count

counter = Counter.remote()
print(ray.get(counter.inc.remote())) # 1
print(ray.get(counter.inc.remote())) # 2
```

#### 3. Object：分布式共享对象存储（Plasma）
集群内跨节点共享大对象（模型权重、数据集、张量），基于共享内存零拷贝传输，避免反复序列化，用 `ray.put()`/`ray.get()` 读写。

#### Ray Core 配套能力
- 内置分布式调度器 GCS（全局元数据存储）；
- Ray Dashboard：Web UI 可视化任务、GPU、内存、日志；
- 自动任务重试、节点故障转移；
- 支持自定义资源隔离、任务优先级。

### 四、五大上层 AI 库（最常用生产组件）
#### 1. Ray Data：分布式数据流水线
分布式加载、预处理海量多模态数据（CSV/图片/视频/文本），衔接训练与批量推理，替代 Spark 做 AI 专用数据流：
- 流式数据预处理、分片加载；
- 与 Ray Train 无缝打通训练数据输入；
- 批量离线 LLM 推理加速。

#### 2. Ray Train：分布式模型训练/微调
统一封装多框架分布式训练，自动处理多机多卡通信，简化大模型训练：
- 支持 PyTorch DDP、FSDP、DeepSpeed、TensorFlow、XGBoost、Hugging Face LLM 微调；
- 自动资源分配、断点续训、GPU 分片；
- 解决原生 DDP 多机集群部署复杂、容错差问题。



#### 3. Ray Tune：大规模超参数搜索
分布式并行跑多组实验，自动调参，支持主流搜索算法（网格/随机/贝叶斯/ASHAScheduler）：
- 同时上百组超参试验，每组独占 GPU；
- 提前终止效果差的实验节省算力；
- 集成 Ray Train，训练+调参一体化。

#### 4. Ray Serve：AI 模型在线推理服务（LLM 主流选型）
生产级弹性推理框架，当前工业界 LLM 服务核心方案：
- 多模型流水线编排（预处理→LLM→后处理独立扩缩容）；
- GPU 分片、动态批处理、流式输出；
- 原生兼容 vLLM、Transformers、FastAPI；
- 弹性扩缩、负载均衡、灰度发布。

#### 5. RLlib：分布式强化学习库
统一 API 实现 DQN、PPO、SAC 等主流 RL 算法，分布式并行仿真环境，适合机器人、游戏、自动驾驶仿真。

### 五、Ray vs 同类框架对比
#### Ray vs Spark
- Spark：擅长**批量结构化数据 ETL**，数据并行；对动态小任务、GPU、有状态服务支持弱；
- Ray：擅长**动态、异构、GPU 密集 AI 任务**，任务并行+Actor 有状态服务；两者常搭配使用（Spark 做数据清洗，Ray 做训练推理）。

#### Ray vs 原生 PyTorch DDP
- DDP：仅解决单机/多机训练，无调度、无服务、无超参调优、无容错；
- Ray Train：统一训练+集群调度+容错+自动扩缩，一套框架覆盖训练全链路。

#### Ray vs Triton/TensorRT Serving
- Triton：侧重单模型高性能推理；多模型编排、动态扩缩、LLM 工作流复杂；
- Ray Serve：原生 Python，灵活编排多模型链路，天然适配大模型微调+推理一体化。

### 1、框架组成



#### 1. **Tensor（张量）**

- 核心数据结构，相当于“多维数组”。
- 用来存储神经网络的输入、输出、权重、梯度等。
- 类似于 PyTorch 里的 `torch.Tensor` 或 Numpy 的 `ndarray`。

------

#### 2. **Computation Graph（计算图）**

- 表示计算过程的抽象结构。
- 节点（Node）：一个运算（比如矩阵乘法、卷积）。
- 边（Edge）：数据依赖关系（张量在算子之间流动）。
- 优点：方便做自动微分、优化、跨设备执行。

> 早期的 TensorFlow (1.x) 强调静态图，TensorFlow 2.x 改为动态图（Eager Execution），更接近 PyTorch。

------

#### 3. **Ops（算子库）**

- “算子”就是基本运算的封装。
- 包括：矩阵乘法、卷积、激活函数、池化、损失函数等。
- 底层由 C++/CUDA 实现，能在 CPU/GPU/TPU 上高效运行。

------

#### 4. **自动微分（Autodiff）**

- 反向传播的引擎。
- 在计算图上应用链式法则，自动生成梯度。
- 用户只要定义 forward，框架自动给出 backward。

------

#### 5. **优化器（Optimizers）**

- 负责根据梯度更新参数。
- 常见的：SGD、Adam、RMSProp。
- TensorFlow 提供了 `tf.keras.optimizers` 模块。

------

#### 6. **模型构建 API**

- **低层 API**：`tf.Variable`、`tf.GradientTape`，适合科研或自定义算子。
- **高层 API**：`tf.keras`，提供 `Sequential`、`Model`、`Layer`，类似乐高积木。

------

#### 7. **分布式训练（Distributed Strategy）**

- 大模型训练必须多卡、多机。
- TensorFlow 提供 `tf.distribute.Strategy`：
    - **MirroredStrategy**：多 GPU 数据并行。
    - **MultiWorkerMirroredStrategy**：多机多卡。
    - **TPU Strategy**：跑在 TPU 上。

------

#### 8. **Serving & 部署**

- **TensorFlow Serving**：推理服务框架。
- **TensorFlow Lite (TFLite)**：轻量化，部署到手机/IoT。
- **TensorFlow.js**：跑在浏览器。
