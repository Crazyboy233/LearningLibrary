# 464_0074.MXF 复检报告（2026-11-11 第二轮，独立全量分析）

> 对象：`464_0074.MXF`，457,011,760 字节，SHA-256 `35e9191a…6b8ab75e`
> 本轮仅做**只读**分析，原文件未修改。所有数字均为**全量**计算，不使用抽样推断。

---

## 一、结论摘要

| 项目 | 本轮独立结论 |
|---|---|
| 视频 essence 是否在文件中 | **不在**，且不是因为"加密强度高" |
| 主结构 | `block[k] = block[0] ⊕ tile(word[k])`，**892,601/892,601 块成立** |
| 块间自由度 | 每块 1 个 32 位 word，且全部 word 落在 **19 维** GF(2) 子空间 |
| 全文件独立信息 | **≈ 2.0 MB**（上界 2.12 MB），远小于 457 MB |
| 尾巴 48 字节 | 同一 tiling 结构的**残块**，非对齐噪声 |
| 前任两处结论 | ① `0xAA0000` 的"第二 partition pack"是**伪证**；② "1.9MB 独立信息"方向正确但未给出秩证明 |
| 可恢复性 | **不可**。数据在写入/导出环节就已丢失，解密无意义 |

一句话：这不是"加密的视频"，而是**一个 512 字节模板 + 每块 4 字节计数器式字段**的退化数据流，视频内容从未进入文件。

## 二、主结构：全量验证

把文件按 512 字节切块，每块视作 128 个 little-endian 32 位字：

```python
a = np.fromfile('464_0074.MXF', dtype='<u4')
B = a[:len(a)//128*128].reshape(-1, 128)
X = B ^ B[0]
ok = (X == X[:, :1]).all(axis=1)
```

结果：`blocks = 892,601`，`ok = 892,601`，`bad = 0`。

即每个 512 字节块内的 128 个字**全部等于同一个 32 位值**，整块只由「块 0 ⊕ 平铺 word」决定：

```
block[k][j] = block[0][j] ⊕ word[k]      (j = 0..127)
```

等价地，`word[k] = block[k][0] ⊕ block[0][0]`。

**这不是一个可以被"解密"加密模型吸收的性质。** 任何可逆变换 `pt = D(c)` 下，若密文块间只有 4 字节差异，则明文块间也只有同样位置的 4 字节差异（在 512 周期密钥流假设下完全相同）。真实视频相邻 512 字节块不可能有 508/512 字节相同。

## 三、关键新证据：GF(2) 秩只有 19

对全部 892,601 个 word 做 GF(2) 消元：

```
rank = 19
pivot bits = {31,30,29,28,27,26,25,24,23,22,21,20,19,18,17,16,15,14,13}
```

含义与影响：

1. **整个 457 MB 文件的块间变化，只张成 19 维空间**，不同取值上界 2¹⁹ = 524,288（实际出现 300,255 种）。
2. 真实的 32 位密码输出会在几千个样本内把秩撑满到 32。19 维是**结构性退化**的指纹，不是密码学输出。
3. 信息量上界：`892,601 × 19 bit ≈ 2.12 MB`；按经验熵算 `H(word) = 17.84 bit` → **1.99 MB**。把 word 序列落盘后 zlib 压到 1.2 MB。

补充：差分 `d[k] = word[k] ⊕ word[k+1]` 的 84 个取值**张成的基与 word 完全一致**（同为 19 维、同一组主元），说明差分不含任何 word 之外的新信息。

## 四、word 序列的生成器形态

这是本轮挖得最深、也是前任完全没碰的部分。

### 4.1 差分字母表极小且几何衰减

相邻差分的取值分布：

| 差分值 | 次数 | 占比 | 1/占比 |
|---|---|---|---|
| `32cca78d` | 438,149 | 0.4909 | ≈ 2 |
| `5755e897` | 223,719 | 0.2506 | ≈ 2 |
| `9c6776a3` | 111,867 | 0.1253 | ≈ 2 |
| `58b9c054` | 55,942 | 0.0627 | ≈ 2 |
| `d104adba` | 25,626 | 0.0287 | ≈ 2 |
| `c27e7666` | 13,990 | 0.0157 | ≈ 2 |
| … | | | |

共 **84 种取值**，前 6 种覆盖 97.4%。严格的 1/2、1/4、1/8… 几何衰减，是**二进制计数器进位链**的指纹：进位传播 k 位的概率正好是 2⁻ᵏ。

### 4.2 转移图近乎确定，且有 2-循环

对 84 符号建一阶马尔可夫矩阵：

- **74/84 个符号只有唯一后继**（列非零数 = 1）。
- 主循环：`32cca78d → 5755e897 → 32cca78d`，回边概率 **1.000**。
- 同理 `9c6776a3 → 32cca78d`（概率 1.000）、`c27e7666 → 32cca78d`（1.000）。

即：绝大多数情况下，看见某个差分就能**确定**下一个差分。这是确定性状态机的行为，不是随机码流。

### 4.3 但它不是块号的线性函数

多项证伪（每项独立）：

| 假设 | 检验 | 结果 |
|---|---|---|
| `word[k] = M·k ⊕ c`（GF(2) 仿射） | 在 k<2¹⁹ 上对 32 个输出位分别消元 | **0/32 位可解** |
| 三元素加性 `w[a]⊕w[b] = w[a⊕b]` | 随机抽 213,909 组 | 命中率 4.7×10⁻⁵（= 2⁻³² 随机水平） |
| `word[k] = f(k mod 2¹⁹)` | 比较 `w[k]` vs `w[k+2¹⁹]` | 相等率 **0.000000** |
| LCG / 几何型 `d[k+1] = A·d[k]` | 统计 `d==D0` 之后的下一个差分 | 49 种不同后继，非单一常数 |
| 常见哈希 `crc32/fnv1a/adler32(k)` | 前 50,000 块 | 精确命中 **0**，落在 word 集合内 3–5/50,000（≈ 随机基线 7/100,000） |

### 4.4 已知的确定性规律（正面结果）

- `word[k] == word[k+64]` 在 **49.96%** 的位置成立（445,888/892,537）。
- `word[k] ^ word[k+64]` 在 **4,715/13,945** 个 64 块窗口内呈**严格常数**；把 word 序列按 64 切行后，13,946 行中只有 9,256 行互不相同（其余为整行重复）。
- `word[0:64] == word[21760:21824]`（完整 64 块重复）。
- 该 64 块对齐性质与本文件是 **64 块 = 32 KiB 为一个物理单元**的写法一致，是固件导出缓冲/条带化的典型痕迹。

结论：word 序列 = 「某个低维状态量」经**非线性但确定性**的置换/进位结构映射而来。它能被完全刻画（84 符号 + 转移表 + 19 维基），但**不含额外信息**——它描述的是"第几块"，不是"这块里有什么画面"。

## 五、修正前任的两处结论

### 5.1 「offset 11141120 命中第二个 partition pack，2⁻⁹⁶ 巧合」→ 伪证

```
word[21760] = 0
21760 × 512 = 11,141,120
```

该块整块与块 0 **逐字节完全相同**，于是前 16 字节自然"重复"。全文件 `word == 0` 的位置**只有 2 个**（0 和 21760），因此这一"命中"不携带任何关于密钥、密钥流或明文的信息。它只是**块 0 被判为重复**造成的必然结果。

这也是第一轮"key[0:12] 已验证正确"推理链的断裂点——用"匹配到模板"反推密钥，前提是匹配点独立；而这里匹配点就是块 0 本身。

### 5.2 「512 字节循环 XOR 加密」→ 与主结构不相容

- 若密钥流 512 周期，则 `block[k] ⊕ block[0]` 应为 0（明文相同时）。实测 100% 是 4 字节平铺 word，意味着明文本身在块间只有 4 字节差异。真实 MXF essence 不具备这种性质。
- 若密钥流非周期，则无法解释为何 `word` 落在 19 维、且差分只有 84 种取值。

两个方向都不成立 ⇒ 问题不在加密层。

## 六、尾巴 48 字节：也是同一结构

文件大小 `457,011,760 = 892,601 × 512 + 48`。最后 48 字节：

```
tail.hex = 0092d0c79f186b95a10d1c303e87a762dd27f27a42ad49287cb83e8de33285df25732eefbaf995bd84ece2181b66594a
```

计算 `tail ⊕ head(前48字节)`：

```
0e144860 × 12（严格 4 字节周期重复）
```

即残块同样满足 tiling 公式，对应 `word = 0x0e144860`。这进一步确认：**生成器在最后一个不完整块上仍在正常工作**，不是截断损坏。

---

## 七、为什么这证明"视频不在文件里"

设任意可逆解密 `pt = D(c)`：

1. **明文约束**：`c` 满足 512 周期 tiling ⇒ 在任意 512 周期密钥流下 `pt` 同样 tiling ⇒ `pt` 的相邻块 508/512 字节相同。视频码流不满足此性质。
2. **信息上界**：`rank = 19` ⇒ 每块独立信息 ≤ 19 bit ⇒ 全文件 ≤ 2.12 MB。457 MB 的视频（即使 H.264 高压缩）不可能塞进 2 MB，且这 2 MB 已被 word 序列用尽。
3. **无 essence 特征**：`06 0E 2B 34` 出现 **0 次**；`ffd8ff`(JPEG) 22 次、`000001`(H.264 起始码) 0 次、`ftyp` 0 次 —— 22 次 JPEG 魔数是 4 字节随机串在 4.57×10⁸ 字节中的期望偶然命中（期望 ≈ 27 次），无意义。

三个独立论证指向同一结论：**写入时 essence 就没进去**，这是导出链路（固件/加密缓冲/预分配）的故障产物。
